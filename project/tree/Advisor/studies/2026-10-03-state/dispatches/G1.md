# Dispatch: what the server sends about game state, and when (G1)
- Brief: map every server-to-client packet (fields, state items, triggers), item identity on the wire, depth/level encoding, and what is never sent.
- Clerk run: 2026-10-03; sources: src/server/net-game.c, tables.c, xtra1.c, xtra2.c, object1.c, object2.c, dungeon.c, cave.c, store.c, util.c, monster2.c, cmd1.c, cmd2.c, spells2.c, src/common/pack.h, defines.h, src/client/net-client.c (to cross-check wire formats), and packet logs runs/observe/session{1,2,3}/pkt.jsonl + session3 screens.jsonl.
- CSV: /projectnb/jbrcs/mangband/Advisor/studies/2026-10-03-state/scratch/G1_packets.csv (43 rows). Scratch decoders: scratch/g1_*.py. All paths below are under /projectnb/jbrcs/mangband/github/src/ unless noted.

## Answer
1. Almost all player state (HP, level, exp, depth, stats, AC, speed, gold, status flags) goes out as **indicator packets** (ids 192..229 = 191+1+IN_x). Each is sent only when a redraw flag is set, in the same server pass that changed it (handle_stuff). Inventory and equipment go out **one packet per slot** (letter, name string, tval, count, total weight). There is no sval, no index and no inscription field; the inscription is inside the name string.
2. Depth is sent as **dungeon level (not feet)** in a **signed 8-bit** field. 0 = town. Wilderness is negative, and **it wraps modulo 256**: wire value 0x21 was displayed by the client as "1650 ft" although the player was in the wilderness (see F6).
3. The character level is sent as (max_plv-or-current, current): `MAX(max_plv, lev), lev` (xtra1.c:166). Exp is (max_exp, exp, exp-needed-for-next-level).
4. Never sent as numbers: monster HP, monster sleep (outside look text), recall timer, light radius, exact food, hero/bless/shield/etc., level feeling, time, deepest depth. Several appear only as message text.

## Findings
1. **Flush mechanism** [SEEN]. Server code sets `p_ptr->redraw` (PR_*), `p_ptr->window` (PW_*), `p_ptr->update` (PU_*) and `p_ptr->redraw_inven` (a u64, one bit per slot 0..35). `handle_stuff` (xtra1.c:3556-3578) runs update_stuff, then `fix_inven`+`fix_equip` if redraw_inven != 0, then `redraw_stuff` (xtra1.c:3249), then `window_stuff` (3468). It is called (a) at the end of every game tick (dungeon.c:2342) and (b) after every network pass for each player (`post_process_players`, net-server.c:490). It returns immediately while `new_level_flag` is set (xtra1.c:3561). So a change reaches the wire in the same server pass as the command or tick, not on a timer. A client sending PKT_REDRAW (c2s 111, recv_redraw net-game.c:1753-1766) makes the server resend everything: `PR_BASIC|PR_EXTRA|PR_MAP|PR_FLOOR`, `PW_*`, `redraw_inven = all bits`. **This is the resync request.**
2. **Indicator packets** [SEEN] (tables.c:567-930; send_indication net-game.c:369-431; IN_ ids mdefines.h:355-392; id = 191+1+IN_x, confirmed in logs, e.g. depth=218, level=195). Value type: TINY = signed char, NORMAL = s16, LARGE = s32, STRING. Fields, trigger flag, and the prt_ function (xtra1.c):
   - level 195, TINY x2: (max(max_plv,lev), lev), PR_LEV, :166. Set in check_experience xtra2.c:1813,1834,1877.
   - exp 196, LARGE x3: (max_exp, exp, adv_exp = player_exp[lev-1]*expfact/100, 0 at level 50), PR_EXP, :181.
   - gold 197, LARGE: au, PR_GOLD, :190 (also sent directly in stores store.c:1285).
   - stat0..5 198-203, NORMAL x3: (stat_use = current incl. drain+gear, stat_top = max incl. gear, flag = stat_top if the stat is 18/100 else stat_top+1), PR_STATS, :122. Internal scale: <=18 literal, above 18 it is 18+n for "18/n" (cnv_stat xtra1.c:21). Log: `[58,68,69]` = current 18/40, max 18/50.
   - armor 204, NORMAL x3: (dis_ac+dis_to_a, dis_ac, dis_to_a), PR_ARMOR, :200 (set only in calc_bonuses when changed, xtra1.c:3033-3037).
   - hp 205, NORMAL x2: (chp, mhp), PR_HP, :209. Set by take_hit (spells1.c:579), hp_player/regen (spells2.c:110,177), calc_hitpoints (xtra1.c:2038). Natural regen goes through hp_player_quiet, so each regen step emits a packet (about 926 hp packets in session 1).
   - sp 206, NORMAL x2: (csp, msp); (0,0) for classes with no spell book, PR_MANA, :215.
   - track 207 (IN_MON_HEALTH), TINY x2: (colour attr, bar length 1..10), PR_HEALTH, health_redraw :1272. Colours: red <10%, light red <25%, orange <60%, yellow <100%, light green 100%; **violet = monster afraid, blue = asleep**; white = tracked monster unseen; (0,0) = none. Length = pct<10 ? 1 : pct<90 ? pct/10+1 : 10. This is the only live monster-health feed, and it covers only the tracked monster.
   - cut 208, TINY: bucket 0..7 (>0:1, >10:2, >25:3, >50:4, >100:5, >200:6, >1000:7), PR_CUT, :429-467. The raw cut timer is not sent.
   - hunger 209, TINY: 0 faint (<500), 1 weak (<1000), 2 hungry (<2000), 3 normal (<10000), 4 full (<15000), 5 gorged, PR_HUNGER, :241-282 (thresholds mdefines.h:242-247). Observed values 0, 3, 4.
   - blind 210, stun 211 (bucket 0..3: >0,>50,>100), confused 212, afraid 213, poisoned 214: booleans (stun as bucket), each with its own PR flag set in set_blind/... (xtra2.c:146,1354,202,308,254). Raw timers not sent.
   - state 215, TINY x3: (paralyzed, searching 1 / 2 for stealth-mode classes, resting), PR_STATE, :363. Sent for each rest start/stop and each search toggle (cmd2.c).
   - speed 216, NORMAL: `pspeed - 110`, plus 10 while searching (undoes the search slowdown), PR_SPEED, :406-413. Observed `fff6` = -10. Weight slowdown is included because pspeed is.
   - study 217, TINY: new_spells != 0, PR_STUDY.
   - depth 218, TINY: `p_ptr->dun_depth` (see F6), PR_DEPTH, :232.
   - oppose 219, TINY x5: (acid, elec, fire, cold, pois) timers, PR_OPPOSE_ELEMENTS, :351.
   - skills 221 (NORMAL x16 = 8 value/factor pairs in order thn, fos, thb, srh, sav, dis, stl, dev), skills2 222 (NORMAL x3 = **num_blow, num_fire, see_infra**), plusses 223 (to-hit, to-dam). calc_bonuses ends with "XXX - Always resend skills" (xtra1.c:3116), so **blows are re-sent after every bonus recalculation**. Observed `[1,1,3]` and `[4,1,3]` for blows/shots/infra.
   - race 192, class 193, title 194, various 220, history 224-227, name 228, gender 229: strings or char-sheet numbers; title via PR_TITLE (also triggers PKT_GHOST, :157).
   - Not present as indicators: light radius, AC breakdown by item, weight/burden, max depth, hero/berserk/bless/shield/invuln/protection-from-evil/see-invis/infra timers. Checked by reading the full indicators[] table (tables.c:567-985) and set_hero (xtra2.c:651-704), which only prints messages and sets PU_BONUS/PU_HP.
3. **Inventory** [SEEN]. PKT_INVEN (30), net-game.c:802-819 / object1.c:2894-2959: `pos` (letter 'a'+index, pack index 0..23, so letters a..x; 'x' is the overflow slot), glyph attr+char, colour attr, `wgt` (u16, **total weight of the stack**, tenths of a pound, weight*number), `amt` (s16 count), `tval`, `flag` (ITF_WEAR 0x01, ITF_ACT 0x02, ITF_FUEL 0x04, ask-aim/ask-item bits), `s_tester`, `name` (object_desc mode 3, with count prefix), `name_one` (**always empty**: `object_desc_one` returns before doing anything, object1.c:2121-2129; the client then copies `name`, net-client.c:2034). **No sval, no object index, no separate inscription field, no charges field.**
   - Name string content (object1.c:1238-2075): quantity prefix ("5 Scrolls of..."); charges "(N charges)" for wands/staffs only if the object is known (:1853); rod "(charging)" / "(N charging)"; torches/lanterns "(with N turns of light)" **regardless of known** (:1923-1928); then `{...}` after the name: the real inscription, or if none "cursed" / "empty" / "tried" / "N% off" (:2015-2071, in that precedence). Logs show `{@r1}`, `{75% off}`, `{on sale}` mixed into names, and unknown flavours as "a Chartreuse Potion" / `a Scroll titled "ishx therbin"`.
   - Empty slots are sent as an entry with name "(nothing)", tval 0, amt 0 (object1.c:1457-1460; logs).
4. **Equipment** [SEEN]. PKT_EQUIP (31): `pos` letter a..l = slot index minus 24 (a wield, b bow, c left ring, d right ring, e neck, f light, g body, h outer, i shield, j head, k hands, l feet; mdefines.h:707-718), attr, wgt, tval, flag, name. The letters collide with pack letters; only the packet type tells them apart. No amt (client sets 1).
5. **When slots are resent** [SEEN code, SEEN logs]. Only slots whose bit is set in `redraw_inven` are sent (object1.c:2920, 2985). No whole-pack resend except login, recv_redraw, PKT_VISUAL_INFO changes (net-game.c:1414) and birth (birth.c:1172).
   - Pickup that stacks: only the stack slot (object2.c:4598).
   - Pickup that does not stack: `inven_carry` sorts the new item into its place and shifts later slots up, marking each shifted slot plus the new one (object2.c:4678-4718). Log, session 2 t=450.25: "You have a Chartreuse Potion (d)." then INVEN d, e, f, g (the new potion and the three slots below it, shifted).
   - Item used up or dropped completely: `inven_item_optimize` (object2.c:4325-4346) slides everything above down, wipes slot 23 and marks every slot from the removed one to 23. Log, session 2 t=414.419: using the last scroll at 'h' produced "(nothing)" for h through x. **Letters of everything after a vanished item change, and the same message shows only the old letter.**
   - `combine_pack` and `reorder_pack` (object2.c:4707-4890) mark each moved slot. They run from `notice_stuff`, which is called in process_player_end (dungeon.c:1069) and is **separate from handle_stuff**. A later tick can therefore re-send a different order, e.g. after an object is identified or becomes "aware" (it then sorts differently, object2.c:4812-4830) [INFERRED from the code order, not seen in a log].
   - Rod recharge: slot resent when timeout reaches 0 (dungeon.c:1607). Torch fuel: slot INVEN_LITE resent only when `pval < 100 || pval % 100 == 0` (dungeon.c:1493-1499; flag set at :1498), so **the displayed turns-of-light is stale by up to 99 turns above 100**. Activation timeout: slot resent when timeout reaches 0 (dungeon.c:1563).
   - Messages come first: "You have X (c)." / "You have no more X." are sent immediately by msg_print; the INVEN packets follow at the next handle_stuff (log order within the same millisecond: MSG then INVEN).
6. **Depth / level** [SEEN code; INFERRED wrap interpretation, backed by log+screen match].
   - `send_indication(IN_DEPTH, p_ptr->dun_depth)` (xtra1.c:234); dun_depth is in dungeon levels, not feet. Feet exist only client-side (`depth_in_feet`, client/c-xtra1.c:302-304: dun_depth*50) and in the server-built status line (xtra1.c:564-570). 0 is "Town" (c-xtra1.c:296). MAX_DEPTH is 128 (defines.h:162).
   - Wilderness uses **negative** dun_depth (dungeon.c:1662,1669 `dun_depth < 0` = wilderness recall; "While in town or wilderness" test `dun_depth <= 0` at dungeon.c:513); MAX_WILD is 4096 (defines.h:166). The wire field is `(signed char)`: net-game.c:399-402, client reads signed char (net-client.c:1031-1034). Anything below -128 aliases.
   - Evidence, session 3 (pkt IND:depth value vs the screen "depth" text at the same instant): wire 0x21 (33) shown as "1650 ft"; 0x5d (93) "4650 ft"; 0x95 (-107) "-5350 ft"; 0xfb "-250 ft"; 0xff "-50 ft"; 0x00 "Town". The screen only echoes the client's own decoding, so the wrap itself is my inference (0x21 = -223 mod 256 fits a player walking between wilderness levels, ending 0xfb, 0xff, 0x00 on the way into town). Whether the server really had -223 is not confirmed.
   - **Level change has no packet of its own.** Chain: `do_cmd_go_down/up` (cmd2.c:117-205) or recall (dungeon.c:1626-1705) or trapdoor etc. changes dun_depth and sets `new_level_flag`; handle_stuff is suppressed; in `dungeon()` (dungeon.c:2058-2275) the level is generated, player placed, then `redraw |= PR_MAP|PR_DEPTH|PR_FLOOR` and `window |= PW_ITEMLIST` and the flag is cleared; the next handle_stuff sends depth indicator, map rows (prt_map), cursor (player position), floor. The depth indicator is the only machine-readable "level changed" signal, and it is not sent if the wire value is unchanged.
   - Character level: see Answer; observed pairs were always equal (1,1) .. (16,16), so the logs contain no drained case. The (max, current) order is confirmed from the server call.
7. **Map and position** [SEEN]. The dungeon is a viewport stream (id 171 for ASCII; DUNGEON_ASCII row/col units are screen cells). `lite_spot` (cave.c:1494-1557) sends one tile (stream_char) when a grid's buffered glyph changed, and always for the player's own grid; `prt_map` (cave.c:1637) sends all rows with RLE on PR_MAP (level change, panel scroll, redraw). No packet carries the panel origin. **Absolute player position arrives only as PKT_CURSOR with vis=MCURSOR_PLAYER (2)**, fields (vis, py, px): the server calls `send_cursor(p, MCURSOR_PLAYER, (byte)y, (byte)x)` against a signature named (x,y), so the first coordinate is y (cave.c:1543; client comment net-client.c:1716-1717). Off-panel: vis=2|0x80, 0, 0 (cave.c:1553). Unknown grids are simply never drawn; walls, doors and stairs are glyph+attr only, there is no terrain-type field.
8. **Monsters** [SEEN]. In view: glyphs in the map stream. The monster list (stream 10 / PW_MONLIST, monster2.c:724-835) is text: one line per race "name ('c')/('c'):[count]", then one line per visible player. **No positions, no health, no sleep, no distance.** It is re-sent only when a monster appears or disappears (monster2.c:1482,1514) or on redraw, not as monsters move; and only if the client subscribed (xtra1.c:1419). Health word and asleep/confused/afraid/stunned come only from look: PKT_TARGET_INFO text "[unhurt, asleep]" (look_mon_desc xtra2.c:3353-3375, send xtra2.c:4255), with screen-relative x,y. Tracked-monster bar: see indicator `track`.
9. **Floor item** [SEEN]. PKT_FLOOR (49): `0, ga, gc, attr, amt, tval, flag, s_tester, name, name_one`, one item only (FLOOR_TOTAL=1, mdefines.h:728). `floor_item_notify` (object2.c:4421-4463) is called on stepping onto a grid (cmd1.c:715-726, 2027), after pickup/drop/use of floor items (cmd2/cmd3/cmd6), and from PR_FLOOR (xtra1.c:683-691, set at level entry dungeon.c:2262 and many item changes). With force=FALSE it skips if `delta_floor_item == o_idx`, so an in-place change to the same object needs PR_FLOOR/force. An empty floor is an all-zero packet with name "" (log: `0000000000000000000000`). Also the text message "You see X." (log).
10. **Level feeling, recall, time** [SEEN]. Level feeling: only message text at generation ("You feel there is something special about this level." etc., dungeon.c:2077-2080 -> cmd4.c:196-211 text table; town: "Looks like a typical town."). Recall: `word_recall` (s16, 15+d20 player-turns at set time, spells2.c:1191) is never sent; messages only: "The air about you becomes charged..." (set), "A tension leaves the air around you..." (cancel), "You feel yourself yanked upwards!/downwards!/sideways!" (fires, dungeon.c:1647-1680). `recall_depth` not sent. Day/night: messages "The sun has risen."/"The sun has fallen." only while dun_depth <= 0 (dungeon.c:517-540); no turn or clock packet. PKT_KEEPALIVE is the client's own timestamp echoed (net-game.c:1121-1131 (recv_keepalive)).
11. **Messages** [SEEN]. PKT_MESSAGE(46): u16 type + text (<=256, MSG_LEN defines.h:48). **A message identical to the previous one and of the same type is sent as PKT_MESSAGE_REPEAT (45, type only, no text)** (util.c:1905-1911). Logs: 160, 264 and 204 such packets in sessions 1-3. A reader that only listens for PKT_MESSAGE under-counts repeated messages ("You hit the X." streaks).
12. **Resists and abilities** (FA, SI, etc.) [SEEN]. PKT_OBJFLAGS (163), 13 rows x 39 cells (attr,char), row = equipment slot 0..11 then row 12 = innate (race/class). Cell columns 1-6: stat boosts and sustains; columns 7-38 = four groups of 8 flags: 7-14 resist acid, elec, fire, cold, poison, fear, light, dark (immunity shown '*'); 15-22 resist blind, confusion, sound, shards, nexus, nether, chaos, disenchant; 23-30 slow digestion, feather fall, perma-lite, regeneration, telepathy, **see invisible (col 28), free action (col 29)**, hold life; 31-38 stealth, search, infra, tunnel, speed, blows, shots, might (xtra1.c:716-1050; flag order mdefines.h:2094-2118). Cell char '+' = present on that item, only counting **known** flags (`object_flags_known`). Sent on PR_OFLAGS, which is set on equipment change and at level 30 crossing (xtra2.c:1820-1830). No whole-character "has FA" bit; the Pilot would have to OR a column over rows 0..12.
13. **Stores** [SEEN]. PKT_STORE per line (pos letter, glyph, attr, per-item weight, number, per-item price, name via `object_desc_store` mode 4) and PKT_STORE_INFO (store name, owner, item count, purse) on entering (store.c:1307-1315); gold re-sent as the gold indicator.
14. **Other s2c packets** [SEEN] (see CSV): one-time login tables (BASIC_INFO, STRUCT_INFO, OPTION, COMMAND, ITEM_TESTER, INDICATOR and STREAM definitions; recv_basic_request net-game.c:1262-1295); TERM/TERM_INIT/TERM_WRITE; AIR and SLASH_FX (cosmetic); SOUND; CHANNEL; PARTY; GHOST (0 alive, 1 ghost, 2 fruit bat, sent with the title). Ids in pack.h never sent by the server: PLUSSES, VARIOUS, HISTORY, LINE_INFO, STUDY, MINI_MAP, SKILLS, PAUSE and others [by absence in server/*.c and client/net-client.h:7-43].

## Contradictions and surprises
- **IN_DEPTH is a signed byte but wilderness depths go to -4095** (F6). Anything deeper than 128 below town in the wilderness wraps and can look like a dungeon level. If the Pilot treats the depth indicator as "dungeon level, negative = wilderness", it will be wrong there.
- `name_one` is always empty (object_desc_one is stubbed out, object1.c:2128) even though it is a wire field; the client falls back to `name`.
- The server-built status line (xtra1.c:509-640, used by character dumps files.c:1280 and xtra2.c:5879) prints "Afraid" when `poisoned` is set (xtra1.c:550-552: the Afraid label is guarded by `if (p_ptr->poisoned)`). Not on the live indicator path, so it does not affect the Pilot; noted as a code bug.
- PKT_CURSOR's x/y parameters are called (y,x) for the player (cave.c:1543); the client acknowledges this in a comment (net-client.c:1716). Trust the wire order (py, px), not the C names.
- Brief says "common 72ec098 level indicator is (max, current)": confirmed from the server (xtra1.c:166); **no log case had max != current**, so the order is not visible in the three logs.

# Dispatch: The dungeon think loop, stairs, and leaving levels
- Brief: D4 — order of decisions in `borg_think_dungeon`, reasons/thresholds for leaving a level,
  arrival handling, stair-finding/scumming, fight-selection filters, and loop/timeout handling.
- Clerk run: 2026-09-28; sources covered: `borg-think.c` (full), `borg-think-dungeon.c` (full,
  2305 lines), `borg-think-dungeon-util.c` (full, 1122 lines), `borg-flow-stairs.c` (full),
  `borg-flow.c` (overview: `borg_flow_spread`, `borg_flow_commit`, `borg_flow_old`, header
  constants), `borg-flow-kill.c` (decision part of `borg_flow_kill`, lines 1651-1917). Also opened,
  for verification only: `borg-caution.c` (`borg_caution`, ~799-1180, needed for Q1/Q2), `borg-
  update.c` (new-level reset, 2046-2145, needed for Q3), `borg-flow-misc.c`
  (`borg_flow_far_from_stairs[_dist]`), and `borg.txt` for config defaults.

## Answer
`borg_think()` (borg-think.c:179) is the single top-level entry point; it updates state once per
call and then calls `borg_think_dungeon()` (borg-think-dungeon.c:1256), a long ordered cascade of
`if (...) return true` gates — safety first, then combat, then loot/exploration, then leaving, then
escalating "get unstuck" behaviors. Leaving a level is driven by many independent triggers (boredom
timer, level-feeling budget, "not prepared" for current/future depth, scary/unique monsters, full
inventory, breeders, low food/light) that all just set `goal.leaving`/`goal.fleeing` flags checked
later in the same function. Arrival on a new level is *not* a special code path — a depth-change
reset (borg-update.c:2049) clears cached danger/known-stairs/flags, and the very next
`borg_caution()` call evaluates danger exactly as any other turn. Stairs are found via a generic
flood-fill "flow" cost map (`borg-flow.c`), and the Borg has three explicit, named stair-scumming
modes (Lunal, Munchkin, and a stair-scum item-grab) that are deliberate exploits. Fight-selection in
`borg_flow_kill` is a pure filter (skip classes/hunger/scary-level/too-dangerous/too-far-from-stairs
/surrounded), not a value calculation — no "value of kill" scoring is computed in this function.
Loop/stuck handling is a fixed ladder: anti-bounce counters, boredom timers, twitch counters, then
bravery boosts, then phase/teleport/recall as last resorts.

## Findings

### 1. Top-level decision order (`borg_think_dungeon`, borg-think-dungeon.c:1256-2301)
Condensed to the major gates in source order (each is `if (cond) return true` unless noted):

 1. Clock-wrap hacks near `time.now`≈12000/25000 or `BORG_TIME_MAX-3000` → reset/panic (1262-1288).
 2. `borg_destroy_floor()` (1295); display delay/redraw (1298-1308).
 3. **Boredom hard cap**: `borg_timer(time.level) >= 10000` → force leaving+fleeing (1311). [SEEN]
 4. `borg_near_monster_type()` — cheat-scan for unique/summoner/scary nearby (1332).
 5. Depth==1 & `fleeing_to_town` → `borg_think_stair_scum()`, else set leaving/fleeing (1340-1363).
 6. `borg_check_bounciness()` (1368), `borg_check_breeders()` (1372) — anti-loop (Finding 6).
 7. Avoidance reset if HP changed → force danger recompute (1376).
 8. **"Short leash"**: if low-HP/low-clevel and far from nearest known upstair
    (> `CLEVEL*3+14` tiles), set `goal.less` to walk back; clears within 3 tiles (1387-1432). [SEEN]
 9. `borg_notice(true)` (1435); **Lunal mode** entry+run (1438-1456, Finding 4); **Munchkin-start
    mode** entry+run (1460-1471, Finding 4).
10. Low-clevel depth correction if current depth is safe: `goal.less=true`, take `<` if on it
    (1474-1488).
11. `borg_think_dungeon_light()` — crucial low-light handling (1493).
12. Twitch decay; `times_twitch>20` → force `goal.fleeing=true` (1497-1502).
13. Continue anti-summon-corridor flow (1507); **`borg_caution()`** — core danger/heal/defend/
    escape/flee-to-stairs gate (1511, Finding 2/6); usually returns true when in real danger, short-
    circuiting everything below.
14. "Bad shape" recovery: no light/cut/poisoned/no food → refuel, recover, drop junk, shop
    (1515-1541); `borg_must_return_to_town()` → leave (1544-1547).
15. Learn spells; wear weapon/digger; dig anti-summon corridor (1550-1565).
16. **`borg_attack(false)`** — attack an adjacent/visible monster (1567). The actual attack commit;
    `borg_flow_kill` (Finding 5) only walks toward a monster.
17. Gear maintenance (wear/swap/rings); grab very-close items (range 5); quiver/ring cleanup; check
    light (1572-1603).
18. Recover: flow to safe grid, `borg_recover()`, `borg_flow_recover(50)` (1606-1616).
19. Perma-spells; "stick near stairs to regen mana" special case for low-level casters (1619-1686).
20. Town with no money/nothing to sell → force leaving (1691-1703).
21. **Flee handling**: `goal.less` (return to stair without using it), then `goal.fleeing` (use any
    stairs) (1708-1750, Finding 2).
22. Flee to safe "Morgoth glyph" grid if relevant (1753-1765).
23. Broad flow cascade: take objects (close→far), kill monsters (close→far, viewable→not, aim),
    vault flow (1768-1805).
24. Inventory chores: use/test/enchant/recharge, drop junk/hole/slow (1813-1838).
25. Flow toward any known object, range 250 (1843-1850).
26. **"Leave the level" trigger**: `goal.leaving` (not recalling/no unique) OR (`CLEVEL<25 &&
    GOLD<25000 && sellable>=13`) → flow to stairs (1855-1890).
27. **Power-dive**: `borg_prepared(CDEPTH+5)==NULL` and not `stair_less` → force `stair_more`, flow
    down (1892-1919). [SEEN, offset = +5]
28. Exploration flow continuations (MISC/DARK/XTRA/BORE/VAULT), vault excavation/chase, "explore
    dark" (1921-1995); `borg_leave_level(false)` unless town money-scumming (1984-1991, Finding 3).
29. Shops; study boring spells if not fleeing; secret-door search; direct-kill fallback
    (1997-2058); recharge before leaving; money-scum in town OR `borg_leave_level(true)`
    (2027-2043); more spastic search/direct-kill (2045-2058).
30. Wait-for-recall rest if safe (2063-2075).
31. Stale-level safeguard: `time.level>800` in town or `>28000` anywhere → mark level stale
    (2084-2086); `no_retreat=5` (2089).
32. **Escalation ladder** (Finding 6): bravery boost #1 → `borg_think_dungeon_brave()`; phase door
    (≤3×); bravery boost #2; bravery boost #3 (wipes known monsters/objects/stairs); teleport (≤5×);
    recall; final "dig to center"/`borg_twitchy()`; else `return false` (2089-2301).

### 2. Reasons to leave/flee a level
All [SEEN] in `borg_leave_level()` (borg-think-dungeon-util.c:605-985) unless cited elsewhere:
- **Boredom budget**: `borg_timer(time.level) > borg_time_to_stay_on_level(bored)` (line 905). The
  budget (util.c:577-599) returns: `CLEVEL*50` if `CLEVEL<10`; `2000`/`2500` if `CLEVEL<15` and low
  food; `z_info->feeling_need*10` while no stuff-feeling known yet; else indexes
  `borg_stuff_feeling[] = {50000, 8000,8000,8000,8000, 5000,5000, 100,100,100,100, 0}` (util.c:
  57-59) by `borg_feeling_stuff` (0-11), halved by /10 for the hard "bored" call. **Surprise**: the
  table *decreases* as the feeling index rises — better reported loot feeling means *less* patience,
  opposite of the intuitive "stay longer for good loot." Not explained elsewhere I read.
- Independently, the hard cap `borg_timer(time.level) >= 10000` always forces leaving (Finding 1.3).
- **Not "prepared" for current depth** (`borg_prepared(CDEPTH)!=NULL`) → climb; if very deep
  (`MAXDEPTH>65`) → return to town instead (util.c:721-785).
- **Bored and can't dive** → climb; **bored and "spastic"** (`avoidance>CURHP`) → climb if unsafe to
  dive else dive (739-754).
- **Power dive if too shallow**: `borg_prepared(CDEPTH+5)==NULL` and not overloaded → dive
  (757-762, duplicated in the main loop, 1897-1919).
- **Full of sellables** (`borg_count_sell()>=12`) → don't descend; low-clevel/gold-worshipping →
  return to town (731-736, 813-825).
- Level/experience drain (`BI_ISFIXLEV`/`BI_ISFIXEXP`) → town (827-837).
- **"Missed town" timers**: `borg_timer(time.town) > 8000` while bored (no vault/unique nearby) →
  rise; `>3500` if scumming 10+ levels below max (840-858).
- Depth-99 special case (retreat to 98 if Sauron dead, not ready for Morgoth); dive if Morgoth dead
  or not prepared for 99 (871-883).
- `BORG_NO_DEEPER` cap (`CDEPTH > borg_cfg[BORG_NO_DEEPER]` → climb); default `borg_no_deeper=127`
  (borg.txt:180), effectively unlimited by default. [SEEN]
- **Danger-driven** (`borg_caution`, not `borg_leave_level`): `pos_danger > CURHP*2` → flee unless
  fighting a unique/in a vault/CLEVEL 50 (borg-caution.c:1086-1099); in town, `pos_danger > CURHP` →
  leave (1100-1111); low on key consumables ("restock") also triggers leaving/fleeing (1063-1085).
- **`borg.mon.scary`** unconditionally forces leaving+fleeing (+`fleeing_to_town` if in town)
  (borg-caution.c:886-911).
- **Breeders**: `>= MIN(CLEVEL+2,5)` breeders with no reliable recall → ignore multipliers, leave,
  flee (borg-think-dungeon.c:1194-1222); a low-clevel-only variant too (borg-caution.c:1266-1276).
- **Anti-loop / too-many-escapes** also force leaving/fleeing — Finding 6.
- A **unique present** generally *suppresses* leaving (several checks explicitly skip while
  `borg.mon.unique` is set, e.g. util.c:774, 907, 846) — the Borg stays to finish it.
- **Stair-scumming as strategy**, not just a leaving reason — Finding 4.

### 3. Arrival on a new level (borg-update.c:2046-2145; outside listed scope, read to answer Q3)
No dedicated "just arrived" function exists. `borg_update()` (called every cycle, borg-think.c:214)
detects `status.old_depth != CDEPTH` and resets: timers, `antibounce_count=1`, `status.vault`,
`mon.unique`, `mon.scary`, `near.breeder`, **`avoidance = CURHP`** (bravery reset),
**`borg_danger_wipe = true`** (forces fresh danger recompute), all "detect X" timestamps, fear
grids. [SEEN] Consequence: the next `borg_think_dungeon()` call runs `borg_caution()` exactly as any
other turn (line 1511) with a fresh danger number; if the arrival grid is dangerous, the *ordinary*
thresholds in Finding 2 fire (e.g., immediate flee-to-stairs if standing on the entry stair and
`pos_danger > avoidance`, borg-caution.c:1116-1121). No special-case "extra caution on arrival"
branch was found.

### 4. Stairs: finding, direction preference, and deliberate scumming
`borg_flow_stair_less/_more/_both(why, sneak[, brave])` (borg-flow-stairs.c) each clear the flow
map, enqueue every known stair of the type (skipping any with a monster on it), run
`borg_flow_spread()` (capped-depth BFS over `borg_data_cost`, borg-flow.c:255-501) then
`borg_flow_commit()`/`borg_flow_old()`. **Up vs down preference**: `borg_flow_stair_more()`
(borg-flow-stairs.c:185-248) refuses to descend if an up-stair is known *and* not lunal/munchkin/
brave *and* `borg_prepared(CDEPTH+1)==NULL` — "don't dive past a known up-stair unless the next
level looks unsafe or I'm scumming." It also blocks descending while hungry/low-food (unless
fleeing a scary town), while overloaded with sellables, or while `goal.recalling`. No equivalent
veto exists for `borg_flow_stair_less()` beyond `birth_force_descend`.
**Deliberate stair-scumming — three named mechanisms, all [SEEN]:**
1. **Lunal mode** (`borg_think_dungeon_lunal`, borg-think-dungeon.c:83-426): gated by config
   `BORG_SELF_LUNAL` (default FALSE, borg.txt:289) and `borg_prepared(CDEPTH+15)==NULL &&
   MAXDEPTH>=CDEPTH+15 && CDEPTH>CLEVEL/3` (1445-1449). Does bare survival (light/hunger/recover)
   then flees to the nearest known stair — up if full of items and one is within 8 tiles (20 on
   depth 1), else down if within 8 tiles or `CDEPTH<30`. Code's own comment: "exploitation
   function... stair scum... to get to the bottom of the dungeon asap" (73-82).
2. **Munchkin mode** (`borg_think_dungeon_munchkin`, 437-921): gated by `BORG_MUNCHKIN_START` while
   `MAXCLEVEL<12` (default FALSE, `borg_munchkin_depth=16`, borg.txt:308-310); same survive-then-
   flee pattern bounded around `BORG_MUNCHKIN_DEPTH`, with some opportunistic attacking first.
3. **`borg_think_stair_scum()`** (util.c:361-572): triggered only at depth 1 with
   `goal.fleeing_to_town` set; grab one nearby item, then flee via stairs; requires an empty pack
   slot.
All three duplicate nearly identical stair-tracking code rather than sharing a helper.

### 5. Choosing fights — decision part of `borg_flow_kill` (borg-flow-kill.c:1651-1917)
Decides whether to *walk toward* a monster (attacking is `borg_attack()`, out of scope). Global
refusals: nothing to kill; in town at `CLEVEL<20` unless money-scumming (1667-1669); spellcaster
below `CLEVEL 35`(dungeon)/`25`(town) — "you are not a warrior" (1671-1675); hungry/weak/starving
(1678-1680); in a Morgoth "sea of runes" (1683-1684). Per-monster filters (any one skips it):
adjacent while afraid; ignored multiplier while `goal.ignoring`; mold-type at `MAXCLEVEL<10`; **any
monster skipped level-wide if `borg.mon.scary`** (1761-1763, broader than avoiding just that
monster); multiplying monsters at `CLEVEL<10`; unique "Maggot"-type in town below `CLEVEL 5`;
requires LOS if `viewable` requested; **danger filter**: `p=borg_danger(...)`, skip if
`p > avoidance/2` (non-unique, `CLEVEL>25`) or `p > avoidance/3` (`CLEVEL<=15`) — deadliness judged
purely against current danger tolerance, no offsetting kill-value term found here; skip monsters
that would pull the Borg beyond `CLEVEL*5+9` tiles from the tracked up-stair while `CLEVEL<10`; skip
group-AI monsters not themselves in a hallway (avoid being surrounded); skip a monster 2 tiles away
with no ranged attack that can still move (could close and hit first); skip via
`borg_flow_far_from_stairs()` (borg-flow-misc.c:1373-1387, active only if `CDEPTH>=CLEVEL-5 &&
CLEVEL<20`, comparing BFS stair-cost to `borg_get_leash(false)`). Survivors are flowed to via the
shared BFS; the *nearest reachable* qualifying monster wins, not the most valuable one.

### 6. Loop/stuck detection and timeouts
- **Anti-bounce** (`borg_check_bounciness`, 1135-1183): `antibounce_count` (incremented every
  `borg_think()` call) at 300-303 clears the current flow goal; at 500-503 forgets *all* tracked
  monsters/objects; at `>=700` forces leaving+fleeing. Purpose per comment: stop a telepathic Borg
  bouncing between spots chasing a monster behind a wall.
- **Escape-count cap** (`borg_caution`, 859-883): `>3` escapes (`>55` while hunting a unique/
  Morgoth) forces leaving (and fleeing if `>3`) below depth 98.
- **Twitch counter**: `times_twitch>20` forces fleeing (1501-1502). Once nothing else fires, a fixed
  ladder runs: boost avoidance to `CURHP*2`, retry via `borg_think_dungeon_brave()`; Phase Door
  (≤3×); boost to `MAXHP*4`, retry; boost to a hard `30000` **and wipe all cached world state**
  (monsters/objects/stairs/glyphs/doors/veins), retry; Teleport (≤5×, several spells/items/scrolls);
  Recall to town; reset memory again, dig toward level center, `borg_twitchy()` (random walk, not
  read in detail); else give up for this call (2089-2301).
- **Clock-overflow guards**: hard-coded windows near `time.now`=12000/25000 clear input and mark the
  level stale (`old_depth=126`, forcing the Finding-3 reset); a second guard panics near
  `BORG_TIME_MAX-3000` (1262-1288). Stale-level safeguard: `time.level>800`(town)/`>28000`(anywhere)
  also forces a reset (2084-2086).

## Transfer notes
- **Ordered gate cascade**: workable as *logic* for a real-time bot, but every "continue an existing
  flow" gate (`borg_flow_old`) assumes the game waited; a reflex-tick Pilot would need to re-check
  "is my plan still valid" against fresh server state each tick instead. [INFERRED]
- **Boredom/time-on-level budget**: transferable *concept*, but Angband's level-feeling mechanic
  doesn't exist in MAngband; would need a substitute "diminishing returns" signal (e.g. time since
  last new loot/monster). [INFERRED]
- **Arrival = no special case**: reassuring — MAngband's Pilot already runs an explicit arrival
  check; the Borg's simpler approach (reset caches, let the normal per-tick danger check handle it)
  works because danger recompute is cheap, which is also true for us. [INFERRED]
- **Stair-scumming modes**: directly relevant precedent for our stair-scum reflex; concrete,
  cheap-to-copy rules: fixed closeness thresholds (8 tiles typical) and "skip a stair with a monster
  on it." [INFERRED]
- **Fight-selection as pure filter, no kill-value scoring**: the Borg leans on danger-vs-avoidance
  plus greedy nearest-target, not cost/benefit of the fight; our danger-table-driven Pilot could
  reuse the "skip if p > avoidance/k" threshold style directly, with "value" coming from our own
  monster-danger memo instead. [INFERRED]
- **Escalation ladder**: useful as a *shape* (increasingly desperate, bounded retries) for "what to
  do when stuck," but items 3-5 rely on Angband consumables/spells our throwaway Warrior mostly
  lacks (no Teleport Level, few Phase scrolls). [INFERRED]

## Contradictions and surprises
- `borg_stuff_feeling[]` (util.c:57-59) awards *less* patience for *better* reported loot feeling
  (50000 → 0 as the feeling index rises) — counter to the intuitive "stay longer for confirmed great
  feelings." Unresolved from what I read; flagged as an open question rather than an explained
  design choice.
- `borg.mon.scary` disables *all* fight-seeking on the level (borg-flow-kill.c:1761-1763), not just
  avoidance of the scary monster itself.
- The three stair-scumming modes duplicate the same "cheat to notice the stair under me" and
  distance-tracking code almost verbatim — confirms they were added separately, not refactored.
- Nothing in the brief's listed sources computes "value of a kill" (XP/loot) — `borg_flow_kill`'s
  logic is danger-avoidance only. If prior notes assumed a cost/benefit kill-value formula lives in
  this file, that is not supported by what I read; it may be in `borg-power.c`/`borg-fight-attack.c`
  (out of my scope).

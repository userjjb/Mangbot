# Dispatch: our Pilot/Navigator today (baseline for Borg comparison)
- Brief: describe our Pilot's/Navigator's danger, caution, depth, main-loop, inventory, perception
  and Pilot/Navigator split mechanisms, with file:line, so the Advisor can compare them to the
  Angband Borg's.
- Clerk run: 2026-09-28; sources covered: `github/tools/pilot/pilot.py` (full, 2311 lines),
  `world.py` (full), `mover.py` (full), `glyphs.py` (full), `pilotctl.py` (full), `HANDBOOK.md`
  (full), `design_pilot.md` (full), `next_steps.md` (the two current "ARCHITECT HANDOFF"
  sections, lines 140-280), `.claude/agents/navigator.md` (full).

## Answer
The Pilot is a single-threaded reflex loop (`Pilot.reflexes()`, pilot.py:1068) with a fixed,
first-match-wins priority list; a `Goal` object (dive/explore/goto/shop/hunt/recall/...) only runs
when no reflex fires. Danger is a rule-based `danger_why()` function (pilot.py:996) merging a
monster.txt-derived breath/blow/paralysis model with a pre-computed CSV danger rating (0-5) from
the Advisor's own table; it sums a pack only for *breath* (`pack_breath`, pilot.py:1045), never
melee, and does not treat stat drain as a danger trigger (only reports it after the fact,
`watch_character`, pilot.py:1813). Caution is an ordered `escape()` cascade (pilot.py:1283): stairs
underfoot > rest (out of combat) > Word of Recall as last resort below 30% HP > Phase Door
(rate-limited) > walk to nearby stairs > numeric potion choice by measured damage rate. Depth is
capped only by a Navigator-set `max_depth` order (feet; 0 = unlimited, pilot.py:128), enforced in
`Dive.tick`/`Explore.tick`, never inferred by the Pilot itself. The Navigator (a Claude subagent,
`.claude/agents/navigator.md`) talks to the Pilot only through `pilotctl.py`'s unix socket (goals,
orders, item actions, `wait-attention`); it never reads Pilot code and gets a curated situation
report, not raw game state.

## Findings

### 1. Danger
1. `danger_why(r, pack_breath)` (pilot.py:996-1041): first-match-wins checks for one monster race
   `r` [SEEN]:
   - `r.level >= lev + danger_level` (default 6) → "lvl N" (pilot.py:1001).
   - UNIQUE and `r.level > lev` → "unique, lvl N" (pilot.py:1003).
   - danger-table rating 5 → "leave on sight"; rating 4 and `lev < r.level+8` → "lethal until
     clvl N+8" (pilot.py:1007-1010) — CSV loaded via `glyphs.load_danger` (glyphs.py:118-130),
     which drops a row silently if its `idx`+`name` no longer match `monster.txt`.
   - capital `D` (ancient dragon) → always out of depth (pilot.py:1012).
   - `r.per_turn >= max(hp,1)/3` (melee/turn = speed × avg blow dice, `Race.per_turn`,
     glyphs.py:77-89), not `NEVER_MOVE` → "melee ~N per turn" (pilot.py:1015). Per-monster, not a
     pack sum.
   - breath: `2*r.max_breath >= hp` or `pack_breath >= hp` where `pack_breath =
     sum(r.max_breath for all monsters in view)` (pilot.py:1021, `dangers()` at pilot.py:1043-1046)
     — **the only place a group's damage is summed**, and only breath.
   - paralysis: HOLD spell or PARALYZE blow (`Race.paralyser`, glyphs.py:60-63), unless
     `free_action=yes`, weighed against armour (`weak_blow`, pilot.py:1026:
     `paralyse_blow_power=2+3*level` vs `ac*3/4`).
   - BRAIN_SMASH without all three of free_action/resist_blind/resist_conf.
   - blinding/confusing *blows* with no save (`no_save_blows`, glyphs.py:72-75), within 10 levels.
   - summoner (spell prefixed `S_`) within 5 levels.
   None check stat-drain; drain only surfaces via `watch_character` (pilot.py:1813-1833) as a
   `stat_drained` event, never feeding `danger_why` or a flee. [SEEN]
2. Arrival check (pilot.py:1104-1120): within 6 s of a level change on stairs, if
   `len(threats) >= arrival_pack` (threats = monsters in view, level ≥ ours-5, default 4) or any
   is individually dangerous, take the stairs back at once (`danger_avoided`, news only). [SEEN]
3. Danger while exploring: `near_danger` — any dangerous monster within 12 squares — drops the
   goal for `Flee` (pilot.py:1122-1131), rate-limited to once/10s (`flee_t`). [SEEN]
4. Unseen attackers: an "It/Something ..." message, or HP falling ≥`max(2.0,1% maxHP)`/s for 4+ s
   with nothing in view and no poison/cut/hunger explaining it (`unseen_tick`, pilot.py:1527-1565)
   → `Flee`, unless minor (teleport-to, missile, arrow/bolt, mumble) at HP above `think_hp`
   (news only). [SEEN]
5. `danger_table.csv` (474 lines incl. header) has many columns (`level,depth_ft,symbol,...,
   breath_avg_max,spells,tags,src_line`); the Pilot reads only `idx,name,danger,speed_x,melee_avg`
   (glyphs.py:127-129) — the rest exist for the Advisor's own reference. [SEEN]

### 2. Caution
1. `reflexes()` order (pilot.py:1068-1262, first match wins): dead/ghost > store lock > emergency
   HP<flee_hp (`escape()`) > status cures in combat > arrival danger > danger in view > unseen
   attacker > choke a pack in the open > afraid handling > repeat-fearer/stationary handling >
   light refuel > hunger > adjacent-monster auto-retaliate > pickup underfoot > auto-destroy >
   rest when hurt & alone > the current Goal > idle (recall after `idle_recall_s`). Matches
   `design_pilot.md:24-50`. [SEEN]
2. `escape()` cascade below `flee_hp` (default 0.5, pilot.py:1283-1396): stairs underfoot first →
   `Recover` goal (rest there; climb back above `max_depth` if too deep, pilot.py:549-578). Out of
   combat (nothing adjacent, no hit in 3 s, HP not falling with something in view) → rest,
   retreating first if something is merely in view — **never quaff potions out of combat**
   (pilot.py:1312-1319). HP<0.3 and can read → Word of Recall last resort (pilot.py:1321-1327).
   Adjacent and can read → Phase Door, every 2.5 s (0.7 s if HP<35%). Not adjacent → walk to
   stairs within 20. Potion choice (pilot.py:1351-1389): `need = max(rate*2.0, 0.1*maxhp if
   hp_frac<0.3 else 0)`, `rate = damage_rate(3.0)` (HP/s over a 3-s window, world.py:235-241);
   weakest potion that beats `need`; if none is big enough and death isn't imminent (`dire =
   rate>0 and hp<rate*8`), biggest potion anyway; if dire, escapes instead. Three emergencies in
   90 s → forced stairs-Flee if any within 30 squares, else just warns (pilot.py:1264-1281). [SEEN]
3. Status cures (`status_tick`, pilot.py:1492-1525), in combat only: stun → cheapest of
   CCW/Healing/*Healing*/Life; confused → CSW+ (monster near); blind → CLW+ (monster near);
   poisoned → Cure/Neutralize Poison or CCW+, only if `hp_frac < think_hp`. [SEEN] Comment
   (pilot.py:94-95) says only CCW+ cures stun/poison, CLW only reduces confusion, citing server
   `use-obj.c:483-545` — not independently re-verified here (out of scope).
4. Fear: kite over walked ground (`retreat_step`, pilot.py:1587-1609) rather than spend
   consumables when not in danger; only in danger (or cornered on arrival, ≥2 monsters) does it
   quaff Boldness/Heroism/Berserk or Phase Door (pilot.py:1146-1171). [SEEN]
5. Phase Door / cure-potion use are rate-limited (2.5 s / 1.5 s) because "repeated phasing doesn't
   shake a pack" and stacking potions under heavy damage is "the commonest fatal mistake" per an
   Advisor-memo comment (pilot.py:1352-1356). [SEEN]

### 3. Depth
1. `max_depth` is a Navigator-set order, feet, default 0 = unlimited (pilot.py:128,
   HANDBOOK.md:125). The Pilot never infers a safe depth from level/gear; it is purely told. [SEEN]
2. Enforcement: `Dive.tick` caps/redirects the target (pilot.py:302-305); `Explore.tick` refuses
   below `max_depth` for non-stairs goals (pilot.py:219-221); `Recover` climbs back above
   `max_depth` once healed rather than resuming deeper (pilot.py:565-578, added because "Dive03
   kept exploring at 1000 ft after fleeing down and died there"); `Flee` prefers an up staircase
   at/below `max_depth` (pilot.py:603-610); `Recall.tick` inscribes `@R<max_depth>` in town so
   recall lands there, not at the deepest level ever reached (pilot.py:640-659). [SEEN]
3. `danger_level` (default 6, pilot.py:112) is a *relative* monster-level gate, not an absolute
   dungeon-depth gate: any monster level ≥ character level + 6, regardless of feet. [SEEN]
4. Who decides: the Navigator sets `max_depth`/`danger_level` via `order key=value` (pilotctl.py;
   HANDBOOK.md:109-129); mission logs show it set per-character (e.g. "max_depth=800" for Dive03,
   next_steps.md:245). [SEEN]

### 4. The main loop
1. `main()`: `while pilot.running: pilot.tick(); client.collect(0.05)` (pilot.py:2292-2294) — a
   0.05 s collect call, so at most ~20 Hz; the module docstring says "~20/s" (pilot.py:6) but an
   in-code comment and `design_pilot.md:24` both say "~10 Hz" — a discrepancy not resolved by these
   sources.
2. `tick()` (pilot.py:1880-1904): drain events → refresh map/status/inventory (rate-limited: map
   0.5 s, status 0.3 s, inventory 10 s or on demand, `World.refresh`, world.py:186-206) → watchers
   (`watch_character`, `watch_breeders`, `watch_progress`, `watch_perception`) →
   `handle_requests()` (pilotctl commands) → `reflexes()` (handled? skip rest of tick) →
   `park_tick()` if parking → `step_goal()` → `idle()`. [SEEN]
3. Goals as classes with `tick(pilot) -> None|(status,detail)`: `Wait`, `Goto`, `Explore`
   (frontier walk, until='stairs'/'upstairs', optional radius), `Dive` (stair-scum, falls back to
   `Search` for secret doors), `Search`, `Hunt`, `Recover`, `Flee`, `Recall`, `Resurrect`, `Shop`,
   `RestGoal` (pilot.py:141-828); one Goal at a time (`set_goal`, pilot.py:1659). [SEEN]
4. Anti-stuck: `watch_progress` (pilot.py:1423-1446) fires `stuck` at ≤10 distinct squares
   visited in 2 minutes while not fighting/resting/idle-goal-type — clears the server queue and
   restarts the move. The Mover itself sends `PKT_CLEAR` whenever it replans off-path
   (mover.py:290-305), fixing a mission-3 10-minute stall (design_pilot.md:52-54,
   next_steps.md:261-263). [SEEN]
5. Navigator cadence isn't Pilot-fixed: `wait SECS` blocks until an attention event or timeout
   (`Handler.handle`, pilot.py:2207-2229). "News" events (`NEWS = {danger_avoided, started,
   tactic, resumed}`, pilot.py:911) never wake a blocked `wait`. With no goal and no Navigator
   contact for `idle_recall_s` (default 600 s) the Pilot reads Word of Recall itself (`idle()`,
   pilot.py:1689-1695). Mission logs show Navigator turns of ~20-49 minutes wall-clock, many
   `wait` calls within (next_steps.md:224-238). [SEEN]

### 5. Inventory
1. Items addressed by pack **letter** (`chr(97+item_index)`, pilot.py:1945, 2166) or a
   case-insensitive **name substring** (`item_index`, pilot.py:1923-1935, 1976-1984).
   Inscriptions (`@r1`, `@1`) are read (`World.tagged`, world.py:281-294) but the only tag the
   Pilot *writes* is `@R<feet>` on a Word of Recall for depth control (pilot.py:657) — no
   combat-swap tagging seen. [SEEN]
2. Two independent lists: `junk` (comma list of "of X" suffixes never picked up, pilot.py:124-127,
   1228-1246) vs. `autodestroy` (pseudo-ID feelings like `worthless,cursed`, items already in pack
   destroyed once so identified, `auto_destroy`, pilot.py:1793-1809). `probably_special`
   (pilot.py:1611-1620) blocks auto-selling `{excellent}`/`{special}`/`{artifact}` or a unique's
   drop unless forced with `sell !NAME` — added after "Wormtongue's armour was sold unseen for 17
   gold" (HANDBOOK.md:143-146). [SEEN]
3. Shopping: `Shop` goal (pilot.py:704-813) — walk to the door, enter, sell (letter/name, sorted
   end-of-pack-first) then buy (cheapest name match), leave; reports the shopkeeper's actual
   message. [SEEN]
4. Swaps: **no dedicated combat-swap mechanism found**. `wear_step` (pilot.py:1839-1851) only
   fills *empty* slots from the pack (one per call, via the `wearall` action) — a one-shot
   "wear what's missing," never a situational swap. [SEEN, absence — see Contradictions]
5. Consumable counts aren't tallied by the Pilot; it re-reads `w.inven` at decision time. The
   HANDBOOK instead tells the *Navigator* to "count Word of Recall in the pack after every
   recall" (HANDBOOK.md:154) — a Navigator, not Pilot, responsibility. [SEEN]
6. Light: the Pilot manages lantern/torch fuel and swap itself (`keep_light`, pilot.py:1759-1791),
   refilling below 3000 turns, added after "Dive03 explored in the dark for minutes." [SEEN]

### 6. What the Pilot can observe
1. Position, depth, the ASCII map + colour attrs (`refresh_map`, world.py:208-222, 0.5 s or on
   move), monsters decoded via unique per-race glyphs (`glyphs.assign`, glyphs.py:179-200; needs
   an uploaded visuals table, glyphs.py:203-206, and server option `avoid_other`,
   pilot.py:2282-2283). The server's `monlist` is a cross-check; `watch_perception`
   (pilot.py:1398-1421) logs when it names something the map-decode doesn't show (documented real
   gap: "a Yellow mold hit us while the pilot saw nothing," pilot.py:1399-1401). [SEEN]
2. Character indicators (`status` query, world.py:190-202): HP/maxHP, six stats (current+top),
   hunger, speed, blows/round, gold, class, level, conditions (`World.flag`, world.py:255-256),
   resting state; last 60 messages (world.py:45); level's item list; inventory+equipment. [SEEN]
3. Cannot observe: monster's *current* HP (only theoretical `max_hp` from monster.txt dice,
   glyphs.py:92-94); a monster's exact per-tick energy (only its base `speed`, converted to
   `speed_x` "actions/player turn" via the CSV or a fallback `max(1.0,(speed-100)/10)`,
   glyphs.py:88); positions between polls (up to 0.5 s stale); anything about other players. No
   `Race`/`World` field carries monster HP or per-tick energy. [INFERRED from their absence in
   every field seen, plus the map-decode's own documented gaps]

### 7. The Pilot/Navigator split
1. Reflex vs strategy: everything in `reflexes()` (danger, emergency escape, status cures, fear,
   stationary monsters, hunger, combat, pickup, light, resting) is Pilot-only, "no waiting on the
   agent" (design_pilot.md:23). Strategy (where to go, dive vs explore, buy/sell/wear, depth
   limits, thresholds like `flee_hp`/`danger_level`/`max_depth`) is entirely Navigator-set via
   `goal`/`order` (HANDBOOK.md:69-130). [SEEN]
2. Interface: one Unix socket per character (`ctl.sock`), JSON request/reply, one connection per
   call (`Handler`, pilot.py:2207-2237); `pilotctl.py` wraps `status`, `goal`, `stop`, `order`,
   item actions (wear/quaff/read/eat/fuel/destroy/drop/inspect/aim/use/zap), `wearall`,
   `inscribe`, `pickup`, `stairs`, `option`, `wait [SECS] [--brief]`, `attention`. `wait-attention`
   is the only blocking call, i.e. the Navigator's "turn" (pilotctl.py:60-78, HANDBOOK.md:12-26).
   [SEEN]
3. Events: **attention** (wakes a blocked `wait`: `goal_done/failed`, `interesting`, `emergency`,
   `fight_going_badly`, `low_supply`, `idle_recall`, `unseen_attacker`, `stuck`,
   `recall_cancelled`, `parked`, `pack_full`, `stat_drained`, `blows_changed`, `breeders` (unless
   weak), `afraid`, `fearer`, `emergency_loop`, `dead`) vs **news** (next report's "Since last
   report", never interrupts: `danger_avoided`, `started`, `tactic`, `resumed`, plus anything
   passed `news=True`) — `NEWS` set and `notify(..., news=)` (pilot.py:911-925). [SEEN]
4. The Navigator agent is barred (by its own prompt and tool list `Bash, Read`) from reading Pilot
   code or any `github/` file except `HANDBOOK.md`, and from starting/stopping anything but
   `pilotctl.py` — "You are a player, not a programmer" (navigator.md:22-24), a role separation
   enforced by convention, not a code sandbox. [SEEN]

## Contradictions and surprises
- **Loop frequency mismatch**: docstring "~20/s" (pilot.py:6) vs. an in-code comment and
  `design_pilot.md:24` both saying "~10 Hz." Not resolved here; real cadence depends on how long
  each `tick()` takes, not just the 0.05 s collect call.
- **No group-melee summation**, despite the brief's expectation: only breath is pack-summed
  (`pack_breath`, pilot.py:1045); melee is per-monster only. A pack of individually sub-threshold
  melee monsters isn't flagged by `danger_why` (though `arrival_pack`/`choke` headcounts trigger
  *other* reflexes). This gap is already on the Architect's open list ("study of pack melee ...
  as leave triggers," next_steps.md:174-175).
- **Stat drain observed, not acted on**: `watch_character` only reports it after the fact; it
  never feeds `danger_why`/`Flee`. Also already an open Navigator suggestion ("repeated stat
  drains ... → leave (like `fearer`)," next_steps.md:168).
- **No item-swap logic**: contrary to a Borg-style expectation, the only wear automation
  (`wearall`/`wear_step`) fills empty slots once; it never swaps gear for a specific threat.
- `load_danger` silently drops CSV rows whose name no longer matches `monster.txt`
  (glyphs.py:118-130) — a silent-mismatch risk with no logged warning.

# Dispatch: how the Angband Borg compares defensive options (prior art)
- Brief: E3 pass 1: Borg defend/escape/heal structure, landing modelling, weaknesses, optional qw comparison.
- Clerk run: 2026-10-25; sources covered: src/borg/ borg-fight-defend.c (3444-3616 plus about 15 of the 33 aux functions), borg-caution.c (60-470, 799-1130, 1630-1860), borg-escape.c (200-520, 640-1000), borg-danger.c (2205-2420, 2795-2867), borg-think-dungeon.c (880-945, 1495-1570), borg-fight-attack.c (5130-5300), git log; qw via WebFetch. Path prefix is `Advisor/data/borg/angband-src/src/borg/`.

## Answer
The Borg is **not** a full "try every option and pick the best" estimator. Only `borg_defend()` works that way. It is a 1-ply, deterministic scan of about 33 *buff-type* defences. Each defence is scored by re-running `borg_danger()` with one flag flipped, and the highest score wins. Healing, escape, retreat and attack are separate fixed-order tiers. Each tier is gated by thresholds on `danger / avoidance`, where avoidance is normally current HP. There are no sequences, no randomness in the decision (only in the landing check) and no worst-case search. Landing squares are modelled only as a 100-sample yes/no safety check, not a score. Our estimator can copy the "flip one state flag, recompute danger" idea. It should not copy the fixed buff bonuses or the unscored escape ladder.

## Findings
1. **Defence pick rule is "max benefit, strict greater-than, first wins."** `borg_defend(p1)` loops `g=0..BD_MAX`, calls each aux in simulate mode, keeps `if (n <= b_n) continue;` (best starts at 0), then re-calls the winner with `borg_simulate=false` (`borg-fight-defend.c:3573-3612`). Ties go to the lower enum index. The enum order (`:68-100`) is BLESS, SPEED, GRIM_PURPOSE, resists, PFE, SHIELD, TELE_AWAY, HERO, BERSERK ... A value of 0 means "do nothing". [SEEN]
2. **Benefit = `p1 - p2`, danger before minus danger after.** For speed, resists, PFE, shield, glyph and door creation, the aux sets a `borg.temp.*` flag (or `borg_on_glyph`, `borg_create_door`), calls `borg_danger(y,x,1,...)`, and restores the flag. Example: `borg.temp.fast = true; p2 = borg_danger(borg.c.y, borg.c.x, 1, true, false); borg.temp.fast = false;` (`:297-299`). The state modelled is a *boolean flag read inside the danger code*. Examples are speed adding +10 to the player's speed in the energy calc (`borg-danger.c:2352`) and resist flags used in the spell/breath damage (`:134-726`). Monster count, HP and positions are never modified in the simulation. [SEEN]
3. **Acceptance rule (common template).** Accept only if `p1 > p2 && p2 <= (unique ? 2/3 : 1/2) * avoidance && p1 > avoidance/7`. That is: the action must help, must bring danger below half of HP (two thirds vs a unique), and there must be something worth acting on. Speed also has a looser branch (`p1>avoidance/5` with a reusable-speed source `good_speed`, else `/7` and `p2 <= avoidance/3`) (`:359-372`). Elemental resists and PFE use `borg_danger(...,average=false)` for both p1 and p2, overwriting the incoming p1 (`:512, :601`), so they compare average-spell danger, not worst-spell. [SEEN]
4. **"Cost vs. consumable value" is by hand-set fudge, not computed.** `p2` is multiplied down to *encourage* use: `*3/10` if a scary monster is on the level, `*7/10` if a unique is near and speed is rechargeable, `*6/10` for a list of named early uniques, `*5/10` vs Morgoth; `p2=9999` to hoard speed late (`:325-355`). Casting fail-rate allowed also scales with danger: `fail_allowed` 25, minus 19 if `p1>avoidance`, minus 10 if above 2/3, plus 10 if below 1/3 (`:272-284`). Item scarcity is handled only by the "already active" check and the `good_speed` flag, not by a price. [SEEN]
5. **Several defences are NOT simulated at all; they return a constant.** Bless returns 1, Hero 1, Regen 1, Berserk 5 whenever `avoidance/10 < p1 < avoidance*0.5` (0.7 vs unique) (`:1291-1425`; bless needs a monster within 3, `:206-237`). Rest returns 200, Teleport Level returns `p1`, Destruction returns `p1 - 0`, Earthquake fakes `p2 = p1/3` or `p1*6/10` by counting 3-4 ranged attackers (`:2285-2300`). So Speed (benefit ~ real reduction) always outranks Hero/Berserk, and a constant 200 or `p1` outranks most real reductions. Scores from different defences are not on a common scale. [SEEN]
6. **Teleport Other is the one "remove monsters" simulation.** `borg_launch_bolt(..., BORG_ATTACK_AWAY_ALL)` computes `p2` as the danger removed by the single most dangerous targetable monster; accepted if `p2 > avoidance/2`. It is skipped if `borg_surrounded()`. A comment states the logic: "if two guys each 500, p2 will be 500, since 1000-500" (`:1111-1285`). [SEEN]
7. **Order in one turn (`borg_think_dungeon`).** `borg_caution()` (`borg-think-dungeon.c:1511`) runs before attack (`:1567`) and before recover (`:1610`). Inside `borg_caution` (`borg-caution.c:1004-1022`), if not already fleeing: **heal, then defend** (mages: defend, then heal). Then: gear swap if danger > avoidance/3; "leaving/fleeing" flags (excessive danger `> 2×HP` sets fleeing, `:1087-1099`); stairs if on them; `borg_escape()` (`:1654`); then "back away" to the neighbour square with lower danger (`:1659-1790`); then cures. `borg_attack()` is last and only reached if nothing earlier acted. Healing precedes defence, and defence precedes escape. A defence that fires returns true and ends the turn, so the escape ladder never sees the situation that turn. [SEEN]
8. **`borg_escape` is a fixed ladder, not a comparison.** Tiers by `b_q / avoidance`: 4.5x (1.5x with no unique), 1.1x for teleport, 1.0x for phase, etc. (`borg-escape.c:717-760, 785-1000`). Each tier is an `||` chain: stairs underfoot, then spells, staff, scroll in a fixed order, with the fail rate relaxed in a second pass. The cheaper phase tiers gate on `borg_caution_phase(25..75, 2)`. First success returns. There is an "emergency phase with no concern for the landing zone" if HP < 10% or danger > 4.5x (`:798-808`). [SEEN]
9. **Heal rule: heal only if it beats the danger, with a random gate.** `danger < curhp + heal && heal > danger/3` ("No rope-a-doping"); also `chance = randint0(100)` against per-HP-band cutoffs (`borg-caution.c:330-400`). [SEEN]
10. **Phase/teleport landing = Monte Carlo yes/no.** `borg_caution_phase(emergency, turns)` draws 100 random squares at distance 5..10 (teleport: 50..100), rejects unknown/wall/monster/web squares, computes `borg_danger(y,x,turns=2,...)` at each, counts "scary" where `p > curhp`, and refuses if `n > emergency` (emergency is a count out of 100: 20, 25, 50, 65, 75 in different tiers) (`borg-escape.c:324-413`, `:417-512`). No averaging of danger, no simulation of the monsters' reaction. Monsters are not moved; danger at the landing square uses current monster positions with a 2-turn horizon. [SEEN]
11. **Danger model is pessimistic and static.** Monsters "walk through walls and other monsters" (`borg-danger.c:2288-2290` comment); fast monsters get multiple hits; `c` (turns) scales the energy; there is a minimum energy so a very fast borg doesn't discount (`:2358-2386`). Spell danger returns the *worst* spell if it is >=1.5x the average or >0.8×HP, else the average (`:2257-2270`). Summons are scored as "only as dangerous as the monster summoned" (`:1458-1460`). The breath/summon geometry and following are not simulated. [SEEN, summons not read in full]
12. **Attack uses the same pattern but a different currency.** `borg_attack()` simulates each attack type and picks max damage with the same `n <= b_n` rule (`borg-fight-attack.c:5149-5300`). `borg_attacking=true` makes danger *ignore PFE benefits* (`borg-danger.c:124`). So attack vs defend is never compared: attack is simply tried after caution returns false. [SEEN]
13. **Known weaknesses.** (a) The authors' own comment: "there will be some times when it is better for the borg to use Destruction instead of Teleport; too often he will die out-of-the-frying-pan-into-the-fire," so they added the landing check (`borg-fight-defend.c:2360-2380, 2440-2460`). (b) Teleport Other benefit "seems wrong," fixed in commit `bcfa7f69` ("teleport away seems wrong. trying to fix calculations"). (c) The comment on `average` documents a flaw: with a resist, an unresisted attack dominates, so the Borg wouldn't cast the resist until they added the `average=false` mode. (d) Oscillation/stuck fixes by counters (see the earlier memo; `70906cb6` "if scared and surrounded, chip at a wall"). (e) `borg_caution_teleport` returns false if *either* `BI_ATELEPORT` or `BI_AESCAPE` is zero (`:431`, `!A || !B`), which looks like it should be `&&`; I did not test. [SEEN; (e) INFERRED]
14. **qw (DCSS bot), structure only.** Per a fetched summary of `source/plans-emergency.lua`: a fixed-priority list `plans.emergency` where the first plan that acts wins; order is stairs/Abyss exits, status cures, escape (teleport, heal), repositioning, then buffs. `want_to_teleport()` fires on HP < 33% with an orb and 2+ enemies, summons present below XL21, or HP<25%. The file has a comment "XXX: This plan is broken due to changes to combat assessment." No simulation. [REPORTED; summarised by the fetch tool, I did not read the Lua]

## Contradictions and surprises
- The brief says `borg_defend()` "tries each defence, computes the danger with that defence applied, and keeps the best." That holds only for about 8 of the ~33 defences (speed, 5 resists/FECAP, PFE, shield, glyph, door). Bless/Hero/Regen/Berserk and the "big gun" spells return constants (finding 5).
- The Borg's healing has a random gate (finding 9), contrary to "deterministic."

## Leads
- `borg_launch_bolt` (borg-fight-attack.c) holds the Teleport-Other "danger removed by a target" logic, which is the nearest analogue to "remove one monster" in our estimator.

## What we should copy / avoid
**Copy:**
- The *flag-flip counterfactual*: compute danger now (p1), compute it again with one assumed state change (p2), score = p1 - p2. It is cheap, uniform, and it already exists in our concept. Apply it to Speed, Berserk/Heroism (to-hit and AC), resists, and "monster gone" (Teleport Other).
- The *acceptance gate*: require p2 below a fraction of HP and p1 above a floor (avoidance/7), so we do not burn consumables on trivial threats.
- *Fail-rate/danger coupling*: when danger is high, only allow reliable actions (`fail_allowed` 25 → 6).
- *Heal only when heal > danger/3 and danger < HP + heal* ("no rope-a-doping").
- *Landing check before Phase*: count how many of N sampled squares would be lethal, and refuse if over a limit. For us, a cheap version is the number of known monsters within 10 squares.
- One knob (avoidance = HP; the Borg uses 2×HP when committed, `borg-think-dungeon.c:2100`) scaling all thresholds.

**Avoid:**
- Constant bonuses (1, 5, 200, `p1`) mixed with real deltas. Put every option on one scale, expected HP lost over the next N seconds, or the ranking is arbitrary.
- Hand-tuned multipliers per unique or scary monster. Use a single stated rule for "worth spending a consumable".
- A strict `>` scan whose ties are decided by enum order. Break ties explicitly (prefer the cheaper or reusable item, then the more reliable action).
- Fallback chains that try 8 methods in one tick (a failed attempt costs a turn). Choose the one action in advance.
- Treating "defence fired" as "escape not needed": the estimator should rank *escape and heal in the same list* as buffs, rather than the Borg's heal, defend, escape fixed order.
- The Borg's one-step greedy view. We should at least evaluate "Phase then fight/quaff" as one option if Phase has a known recharge-free cost, since the Borg's own comments admit a bad landing is its main death mode.

Note: the Borg does no multi-action planning; any 'phase then heal' emerges from re-evaluating each turn (INFERRED from finding 7-8: no search found).

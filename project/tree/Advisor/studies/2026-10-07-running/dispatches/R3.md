## Answer
The Pilot plans its own Dijkstra path on remembered tiles (mover.py `plan`) and executes it tick by tick. In the dungeon it runs whenever a straight stretch of >=3 tiles lies ahead (or, in corridors and dark rooms, lets the server's run follow the corridor) and walks otherwise. A run is `custom . dir=D`; it is cancelled with a `walk 5`, which the server swallows. On the surface (town or wilderness) runs are switched off entirely by `runs_ok()` (a516853). The only monster rule is "any visible monster within 5 squares". There is no map-border, light or dark-room rule beyond that. No simulator or unit tests for movement exist.

## Findings
1. **Planner** [SEEN] (mover.py:22-72). Dijkstra, 8-way, `max_cost` 4000. Costs: door `+` 3, trap `^` 25, `8` 50, rubble `:` 15, unknown +1, diagonal +0.001, monster tile or tile next to a NEVER_MOVE monster +40. The dungeon treats unknown as impassable (it is goal-only) and walls `#%*` and digits as blocked. The surface (`world.in_dungeon` False) treats unknown ground as open, and blocks `#*=%0:` and shop digits 1-7 except `8` (the Tavern). Rows 1..64 and columns 1..196 only (MAX_HGT 66, MAX_WID 198).
2. **Walk pipeline** [SEEN] (mover.py:368-380, 82-83). Sends `walk D` and queues up to AHEAD=2 steps beyond those reached, because the server drops a walk if >2 are queued (net-game.c:1930-1950, "Classic MAnghack"). Progress is detected when `world.pos` matches `path[done:sent+1]` (mover.py:297-301). STEP_TIMEOUT 1.5 s with no progress sends `clear`, avoids that tile and replans. At most `max_replans`=8 per goal, then "stuck". Off-path (push, dropped step, teleport, run bend) means `clear`, `walk 5` if running, then replan (mover.py:302-317). A bump ("blocking your way") marks `:` or `#` and replans or digs with `custom T dir=` (mover.py:321-336, 221-250).
3. **Walk vs run decision** [SEEN] (mover.py:355-380). A run starts only if ALL hold: `sent == done` (nothing queued), `runs_ok()` (`use_runs` is always True; `in_dungeon` is not False), and no monster within 5 (Chebyshev, `w.dist`).
   - If the straight stretch (`_straight`) is >= RUN_MIN=3: `custom . dir=D`, remember `running=(done, done+n)`.
   - Else, if `in_corridor()` (<=3 open neighbours) and >=3 steps remain: `free_run(d, keep_goals=True)`, which sends `custom . dir=D` and lets the server follow bends. When it ends (no movement for 0.5 s) the Mover replans to the goals.
   - Else it walks, but it stops queuing walks when the next index is runnable (mover.py:369-370), so a run can start after the queued steps land.
4. **Run tracking** [SEEN] (mover.py:118-134). `_run_tick`: sends `walk 5` when a monster comes within 5, or when `done >= end-1` ("stop one tile early"). The run is considered over after 0.8 s with no progress, or 0.5 s after the stop was sent. Overshoot or bend shows up as pos not on the path, which triggers the clear and replan from finding 2. `_free_tick` (mover.py:164-192) also sends `walk 5` on a monster within 5 or on reaching a goal tile. Free runs end after 0.5 s without movement and return "arrived" if the Pilot moved, else "stuck".
5. **Explore adds its own free runs** [SEEN] (pilot.py:334-346, commit 835181c). After planning to a frontier, `free_run(d)` if the path exists, no monster within 5, no `radius` is set, and (`in_corridor()` or path length <=2). The reason was that 60 of 71 plans were single steps in dark rooms. If a free run ends "stuck", `no_run_at` records the square and the Pilot walks from it next time (pilot.py:312-313). Explore refuses on the surface (pilot.py:286-289).
6. **Speed constants** [SEEN] (mover.py:82-83,104; commit messages). AHEAD 2, STEP_TIMEOUT 1.5, RUN_MIN 3 (was 5 before 6c3cea5), run-end timeouts 0.8/0.5/0.5 s. Server: ~0.5 s per walked step, ~0.1 s per run tile [REPORTED] (operations.md:100, next_steps.md:68-72). Measured gains: 6c3cea5 2.2 -> 5.5 tiles/s across town; 835181c 2.0 -> 2.9 tiles/s; ecb1a5f 1 tile/41 walks -> 89 tiles/60 s.
7. **Other movement outside Mover** [SEEN]. Single `walk D` through `p.cmd` for the Temple step (pilot.py:793), leaving the town edge (844), entering a store (977) and stepping away from threats (2275). The server's `pathfind` is not used, because it treats unseen grids as open and walks off the level (next_steps.md:72-76 [REPORTED]).

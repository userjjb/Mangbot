# Step 3 done: which rulebook tables the Pilot now depends on (Architect → Advisor, 2026-10-23)

So you know what a rulebook change affects. All of these are read from the synced copy in `github/tools/rulebook/`
(I run `sync.sh` after each release):

| table | the Pilot uses it for |
|---|---|
| `monsters.csv` | ratings, speed_x and melee_max for every race (it replaces the 09-27 danger table; at level 40 or below only your 3 re-ratings and 2 speeds differ). `veto_reason` and the fight rows feed the hunt check |
| `monsters_raw.csv` + `fight_sim.py` | the hunt check's p90 |
| `kinds_by_level.csv` | junk kinds (worthless at every level, or value ≤ 1): the same 38 kinds as my old list. Also unknown-flavour values |
| `jewellery.csv` | a ring or amulet of a known kind whose plusses aren't shown: E[value] and P(cursed copy) (~45% for Protection, Strength, Damage...). It counts as unidentified, so it's never worn and is identified before selling |
| `feelings.csv` | pseudo-ID'd gear (unchanged) |
| `abilities.csv` | ability proofs in play: Free Action, rBlind, rNexus, hold life, the sustains, feather fall (has-evidence only; I left out the "has OR save" lines) |
| `shop_owners.csv` (via shopmath) | the pay rate per shop and owner at the current CHR. This replaces the flat 38%; six recent sales came out exact |
| `drops.csv` | `monster NAME` now gives the expected drop |
| `constants.csv` | checked against the Pilot's assumptions (recall 15-34 blocks, store maintenance 33 s, fuel): consistent. The recall goal now rests while it charges when hurt and nothing is in view (recall_seconds: 10× while resting) |
| `rule.py` | the Navigator can run `pilotctl rule ...` |

If a column is renamed or its meaning changes, please say so in the release memo: the loaders fall back to old files
or defaults, so a mismatch would be quiet.
